# Архитектура Breakly

## Границы

Один пользовательский процесс и одна STA-очередь `GetMessage`. Собственных рабочих потоков и служб нет. Системные библиотеки могут создавать потоки по мере необходимости. Ядро не включает Win32 и тестируется без рабочего стола. Зависимости только из Windows SDK и стандартной библиотеки C++.

| Компонент ТЗ | Реализация | Ответственность |
|---|---|---|
| ActivityMonitor | `platform.cpp`, `ActivityMonitor` | Только GetLastInputInfo, без хуков и содержимого ввода |
| BreakScheduler, SessionStateManager | `core.cpp`, `Scheduler` | Длительности, независимые категории, явные состояния |
| BreakPolicyEngine | `core.cpp`, `Scheduler::due/allowed`; `platform.cpp`, `BreakPolicyEngine` | Приоритеты, расписание, полноэкранное окно |
| NotificationManager | `main.cpp`, `App::show/update`; `ui.cpp`, `View` | Единственное напоминание, действия, повторы, доставка |
| TrayManager | `main.cpp`, `App::tray/menu` | Shell_NotifyIcon, меню, TaskbarCreated |
| AutostartManager | `platform.cpp`, `AutostartManager` | HKCU Run с кавычками и `--background`, только после согласия |
| SettingsService | `storage.cpp`, `FileStore::load/saveSettings` | Проверка схемы, восстановление и атомарная запись |
| StatisticsService | `core.cpp`, `Daily`; `storage.cpp`, `FileStore::load/saveStatistics` | Дневные агрегаты, последние семь дней |
| SystemEventMonitor | `main.cpp`, `App::proc`; `platform.cpp`, `SystemClock` | WTS, питание, дисплей, часы и тема |
| LoggingService | `storage.cpp`, `LoggingService`; `FileStore::error` | Только ошибки в ограниченном `errors.log` (64 КиБ), без содержимого ввода; сообщение в обзоре |

Для небольшого процесса обязанности сгруппированы по границам, а не превращены в набор служб и контейнер DI. Интерфейсы `IClock`, `IActivity`, `INotifications`, `IStore` позволяют подменять системные источники; в тестах `Scheduler` получает детерминированные `Sample` напрямую.

## Время и активность

Монотонное время `GetTickCount64` управляет длительностью перерывов, паузой и откладыванием. `QueryUnbiasedInterruptTime` ограничивает начисление работы временем бодрствования, даже если пропущено событие питания. Календарное время используется для дат статистики и расписания; изменение часов не меняет длительности. Различие часов описано в [документации Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/realtimeapiset/nf-realtimeapiset-queryunbiasedinterrupttime).

Опрос активности — раз в 15 секунд. Последняя граница ввода вычисляется из GetLastInputInfo с беззнаковым вычитанием для перехода через 32-разрядный счётчик. Отрезок после порога бездействия не начисляется. В чтении/видео экранное время продолжает учитываться; время блокировки и сна исключается всегда. Показатель «с недавним вводом» — оценка участков с вводом за последние 15 секунд, а не измерение времени движения мыши.

Бездействие от двух минут приостанавливает начисление. От пяти минут оно становится кандидатом на отдых и прерывает непрерывную сессию; выполненный отдых автоматически не подтверждается. После достаточно долгой блокировки/сна соответствующие категории могут получить фактическую паузу; пользователь может отключить такой сброс. Короткая пауза сбрасывает только категории с длительностью отдыха не больше этой паузы. Законченный по таймеру отдых требует подтверждения по кнопке.

При пропуске очередной интервал выбранной категории начинается заново. Остальные категории сохраняются. Полноценный отдых удовлетворяет короткие категории, если его длительность действительно достаточна. Просроченные события не помещаются в очередь: выбирается только самая важная категория из текущего состояния.

## Состояния

| Состояние | Вход | Выход |
|---|---|---|
| Working | Обычная активность | Бездействие, срок категории, пауза или системное событие |
| Idle | Нет ввода дольше порога, режимы чтения/видео выключены | Новый ввод или системное событие |
| BreakDue | Наступил срок или показано предложение | Начать, отложить, пропустить, пауза |
| BreakActive | Пользователь начал отдых | Подтверждение после срока или досрочное завершение |
| Snoozed | Предложение отложено | Срок откладывания, более важная категория, пауза |
| Paused | Ручная пауза, нерабочие или тихие часы | Конец паузы, возобновление, разрешённое расписание |
| Suspended | Сон или отключение дисплея | Возобновление или включение дисплея |
| Locked | WTS_SESSION_LOCK | WTS_SESSION_UNLOCK |

Приоритет конфликтов: сон → блокировка → уже начатый отдых → пауза/расписание → ожидающее предложение → самая важная наступившая категория → откладывание → бездействие → работа. Уже начатый отдых может продолжаться на паузе, новые предложения не выдаются. После сна не создаётся очередь старых окон. Скрытое при блокировке окно не перерисовывается.

## Ресурсы и диск

Невидимое служебное окно принимает широковещательные события. Один перевыставляемый таймер назначается на ближайшее событие, но не дальше следующего опроса активности (15 с). Отдельный секундный таймер существует только у видимого окна для текста обратного отсчёта; на скрытии и минимизации он останавливается. Ни Present-цикла, ни timeBeginPeriod нет.

Direct2D, DirectWrite, кисти и шрифты создаются при открытии `View`. HWND и COM-ресурсы уничтожаются при закрытии. Для простой сцены выбран программный Direct2D render target: измерения показали меньшую память и стоимость открытия окна без GPU-контекста приложения. DWM Mica запрашивается только на поддерживаемых сборках Windows 11 (22621+), при прозрачности и без высокого контраста; граница поддержки проверена по [описанию DWMWA_SYSTEMBACKDROP_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute). Материал используется в верхней полосе главного окна, нативные GDI-контролы расположены в непрозрачной части. Уведомление использует непрозрачную системную поверхность. Анимация ограничена системными переходами DWM и отключается по настройкам доступности.

Статистика записывается только при изменениях, раз в пять минут, при уходе в сон и штатном завершении. Настройки — по кнопке сохранения. Используются FlushFileBuffers и MoveFileEx с заменой; частично записанный временный файл не загружается. Повреждённые исходники сохраняются отдельной копией. Одиночный экземпляр ограничен SID пользователя, сеансом и профилем, повторный ручной запуск открывает существующий экземпляр через сообщение без передачи командной строки.
